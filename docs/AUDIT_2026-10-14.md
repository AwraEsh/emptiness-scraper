# Reliability audit — 2026-10-14

## Changes in 1.0.1

- Confirmed account aliases now form one participant before turns, responses, restarts, and rule events are calculated. Source message objects remain unchanged.
- Message IDs sort numerically within each source for equal timestamps. Different exports retain independent ID namespaces, including files with identical basenames.
- Explicit replies resolve only inside their source export. Unresolved targets are counted and reported rather than guessed from another account's message IDs.
- Duplicate detection includes message ID and media metadata. Repeated messages inside a single export retain their multiplicity. Deduplication remains conservative across accounts.
- Telegram JSON with a UTF-8 BOM is supported. Malformed records fail explicitly; service and rich message records are handled separately. Missing epoch values use the chosen export-device timezone.
- Session thresholds reject zero, negative, infinite, and NaN values. Timezone offsets reject invalid hours and minutes. Incomplete intervals require ordered aware timestamps.
- Quarter boundaries no longer count sessions twice. Inactive Gregorian months remain visible. Periods include raw and comparison-safe message/session counts and month-over-month changes; a missing denominator produces null rather than an invented percentage.
- Restart rates include their opportunity denominators. Latency summaries are available by participant, month, weekday, hour, and raw/comparison-safe mode.
- Emoji counting preserves flags, keycaps, skin tones, and joined sequences. Persian diacritics and tatweel no longer split normalized words.
- Phrase counts preserve contiguous words and sentence boundaries. Disabled rule collections stay disabled, and matched events identify the exact pattern and comparison-safe status.
- Corrupt settings fall back to validated defaults. Settings writes use an atomic temporary-file replacement. Invalid regex rules are rejected before saving.
- Markdown includes complete temporal comparisons, definitions, reaction-received labels, latency percentiles, and audit warnings. CSV neutralizes formula-like strings; JSON retains the original strings. Markdown table cells escape embedded HTML, pipes, and line breaks.
- Wizard paths accept single or double quotes and semicolons inside quotes. Previous reports can be read inside the wizard. Identity suggestions are explicitly described as heuristics.
- Both launchers check installed dependency constraints locally before attempting network installation. Repeated launches can run offline once dependencies are satisfied.
- Parser memory overhead is reduced by retaining only required media metadata. Session turn counts and normalized stopwords are computed once rather than repeatedly scanning the same data.

## Verification

Regression fixtures are entirely synthetic. Tests cover alias transitions, same-second ordering, exact period boundaries, silent months, missing reply targets, malformed settings/exports, Unicode emoji, Persian normalization, complete report generation, spreadsheet-safe CSV, and full wizard input/output.

Distribution tests execute the Unix launcher offline. A Windows-only integration test creates a fresh environment with `run.bat`, then runs it again with an unreachable package index to verify offline reuse. Python 3.11 grammar compatibility is checked for every application module. CI runs Python 3.11 and 3.13 on Windows and Ubuntu.

## Boundaries

Participant suggestions use message-volume heuristics and must be confirmed. Identity cannot be established from display names alone. Account-local message IDs are never treated as globally unique.

Reading JSON currently loads one complete export at a time; this is not a streaming parser. Maximum-detail Markdown and CSV outputs can be large. Session size statistics are attributed to the session's start period and include the full session.

Reactions attached to a message count as reactions received. Determining who gave a reaction requires additional metadata and is not inferred here. Timing and text patterns do not establish feelings or intent.

The existing v1.0.0 release asset remains unchanged. This audit updates the source version to 1.0.1; a new release requires its own packaging step.
